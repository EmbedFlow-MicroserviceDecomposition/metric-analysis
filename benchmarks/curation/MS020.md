## Decisions
| # | Decision | Basis |
|---|---|---|
| D1 | src_class = the Feign client interface (e.g. `AuthServiceClient`), src_method = its method | Team rule: the class+method that issues the request (MS001/MS032 D4 precedent) |
| D2 | Endpoints include the servlet context-path from `config/src/main/resources/shared/<svc>.yml` | Feign paths (`/uaa/users`, `/statistics/{..}`, `/accounts/{..}`) only resolve to controllers with the context-path |
| D3 | OAuth2 token validation (`CustomUserInfoTokenServices.getMap` → `/uaa/users/current`, plus the framework's own `UserInfoTokenServices` in notification-service) and client-credential token fetches (`/uaa/oauth/token`) are **not** calls | Ravishan's decision (2026-11-18): security infrastructure, like discovery/config; keeps all 3 resource servers consistent |
| D4 | `ExchangeRatesClient` → `https://api.exchangeratesapi.io` is not a call | External third-party API, not a service in the system |
| D5 | RabbitMQ carries only Spring Cloud Bus and Hystrix/Turbine metrics; no business messages | No `@RabbitListener`/`@StreamListener`/`RabbitTemplate` in application code; dependencies are `spring-cloud-starter-bus-amqp` and `turbine-stream`/`stream-rabbit` |
| D6 | Gateway static JS (`gateway/src/main/resources/static/js/*.js`) is browser code, not service interfaces | Runs in the user's browser; the draft wrongly listed 153 of its functions as gateway interfaces |
| D7 | Principal parameters stripped; `getUser` return type kept as `Principal`, `RecipientController` returns kept as `Object` | Normalisation rules; declared return types are not wrappers |

## Runtime check (2026-11-18)
Docker Hub `sqshq/piggymetrics-*:latest` images were built 2021-01-19 from commit `fd5ee3c`; the only changes between `fd5ee3c` and the analysed `master` are to `README.md` (GitHub compare API), so the images run exactly the analysed code.

**Setup:** all 14 containers from `docker-compose.yml`, amd64 under emulation, gateway on host port 4000. The only behavioural change is in config: the config server reads a copy of `shared/*.yml` in which `backup.cron` is `0 * * * * *` (every minute) instead of `0 0 12 * * *`, so the scheduled backup job (call 3) runs during the test. `scenario.sh` signs up, logs in (password grant), and calls all 11 endpoints through Zuul, then saves notification settings with a BACKUP that is due and waits for the job. Evidence is in `MS020_runtime/`.

**Inbound HTTP observed** (tcpdump on ports 5000/6000/7000/8000, source IP mapped to container; full table in `http_summary.txt`):

| GT call | Observed | Result |
|---|---|---|
| 1 account `AuthServiceClient.createUser` → auth `POST /uaa/users` | 1 request from account-service | ✅ confirmed |
| 2 account `StatisticsServiceClient.updateStatistics` → statistics `PUT /statistics/{user}` | 1 request from account-service | ✅ confirmed |
| 3 notification `AccountServiceClient.getAccount` → account `GET /accounts/{user}` | 2 requests from notification-service (one per run of the backup job) | ✅ confirmed |

**Excluded traffic, observed as predicted:** `GET /uaa/users/current` from account (5), statistics (4) and notification (2), which is token validation (D3). `POST /uaa/oauth/token` from account and notification is client-credential token fetching before their Feign calls (D3). All other requests came from the gateway (config-only routes).

**No unlisted edges:** no other service-to-service HTTP request was seen. RabbitMQ carried only Spring Cloud Bus/Turbine traffic (D5).

**Environment issues, not call-graph issues:**
- statistics-service failed to save the PUT because the external `api.exchangeratesapi.io` now returns 401 (it needs an API key), so account-service logged `StatisticsServiceClientFallback`. The request still reached statistics-service.
- The backup email fails (dummy Gmail credentials), so the recipient is not marked notified and the job repeats each minute. That is why call 3 was seen twice.

**Limit:** confirms that the 3 calls happen and that none other was triggered by the 11 endpoints plus the scheduled backup job. The REMIND job (no cross-service call in code) was not triggered.
